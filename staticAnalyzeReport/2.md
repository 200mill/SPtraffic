## Critical

### NC-1 · Hardcoded fallback password in `docker-compose.yml`

| Field | Detail |
|-------|--------|
| File | `docker-compose.yml:61` |
| Severity | **Critical** |

```yaml
DB_PASSWORD: ${DB_PASSWORD:-changeme}
```

If `DB_PASSWORD` is unset (e.g. missing `.env` file on the server), Docker silently substitutes `"changeme"` and the container starts with a guessable credential. The image is public via GHCR; anyone who pulls it and runs it unmodified gets a live database with a known password.

**Fix**: Remove the default. Fail-fast if the variable is absent:
```yaml
DB_PASSWORD: ${DB_PASSWORD:?DB_PASSWORD must be set}
```

### NC-2 · `UNIQUE` on nullable `routes.code` allows unlimited duplicate-NULL rows

| Field | Detail |
|-------|--------|
| File | `backend/migrations/002_create_routes.sql:3` |
| Severity | **Critical** |

```sql
code VARCHAR(30) UNIQUE   -- NULL allowed
```

PostgreSQL's UNIQUE constraint treats every NULL as distinct, so `INSERT … code = NULL` never conflicts. The ingestion comment says "Routes without an API-provided code are inserted without ON CONFLICT handling" — meaning every daily full-refresh creates a new copy of every code-less route instead of updating the existing one. Over weeks the table balloons with duplicate routes, breaking search result deduplication.

**Fix**: Use a partial unique index instead:
```sql
CREATE UNIQUE INDEX idx_routes_code_notnull ON routes(code) WHERE code IS NOT NULL;
```
Drop the column-level `UNIQUE` from the `CREATE TABLE`.

## High

### NH-1 · Raw DB/Redis error strings returned in `/health` response

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/handler/health.go:37,42` |
| Severity | **High** |

```go
status["db"]    = "unreachable: " + err.Error()
status["redis"] = "unreachable: " + err.Error()
```

Error messages can contain internal hostnames, port numbers, usernames, and driver version strings (e.g. `"failed to connect to host=internal-db user=sptraffic database=sptraffic: dial error"`). The `/health` endpoint is unauthenticated and commonly exposed to load-balancer probes — and sometimes to the public internet.

**Fix**: Log the full error internally; return only a binary status to callers:
```go
log.Printf("db health check failed: %v", err)
status["db"] = "down"
```

### NH-2 · `X-Admin-Key` missing from `Access-Control-Allow-Headers`

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/middleware/cors.go:14` |
| Severity | **High** |

```go
c.Header("Access-Control-Allow-Headers", "Content-Type")
```

Browsers send a CORS preflight before any request that includes a non-standard header. Because `X-Admin-Key` is not listed, the preflight is rejected and the browser never sends the actual `POST /api/admin/ingest` or `GET /api/admin/status` request. Admin endpoints are completely inaccessible from any browser-based client.

**Fix**:
```go
c.Header("Access-Control-Allow-Headers", "Content-Type, X-Admin-Key")
```

### NH-3 · GitHub Actions deploy job runs with implicit `write-all` permissions

| Field | Detail |
|-------|--------|
| File | `.github/workflows/ci.yml` (deploy job) |
| Severity | **High** |

The `deploy` job has no `permissions:` stanza, so it inherits the workflow-level default — `write-all` on repositories that have not restricted it. A compromised step or a malicious dependency in that job can push code, create releases, or modify CI configuration.

**Fix**: Restrict to the minimum needed (SSH deploy needs no GitHub API permissions):
```yaml
deploy:
  permissions:
    contents: read
```

### NH-4 · Search results not deduplicated — duplicate journeys returned to users

| Field | Detail |
|-------|--------|
| File | `backend/internal/service/search_service.go` (`oneTransfer` function) |
| Severity | **High** |

The transfer-search loop iterates all `(route1, schedule1, route2, schedule2)` combinations. If two different routes share identical times on the same leg (e.g. two operators running the same schedule), the user sees the same journey twice with different route IDs — giving the false impression of more options.

**Fix**: Deduplicate by journey key after collecting results and before truncating to `maxResults`:
```go
type journeyKey struct{ dep, arr, via int }
seen := map[journeyKey]bool{}
var deduped []domain.SearchResult
for _, r := range results {
    k := journeyKey{r.Legs[0].DepartureMins, r.Legs[len(r.Legs)-1].ArrivalMins, r.Legs[0].To.ID}
    if !seen[k] { seen[k] = true; deduped = append(deduped, r) }
}
```

### NH-5 · Rate-limiter cleanup goroutine races against `getLimiter`

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/middleware/ratelimit.go:24–34` |
| Severity | **High** |

The background cleanup goroutine holds `mu`, deletes stale visitor entries, then releases `mu`. Immediately after release, `getLimiter` can re-insert the same IP. On the next cleanup tick, the freshly-created limiter is deleted again because `time.Since(v.lastSeen)` was just reset — the logic is correct — but this is subtle and could misbehave if the ticker fires faster than the `lastSeen` threshold. More importantly (overlap with C-2 from report 1), the goroutine runs forever with no stop mechanism.

**Fix**: Replace `time.Tick` with `time.NewTicker`, store it, and stop it on server shutdown via a done channel.

## Medium

### NM-1 · Empty-string default for `DB_PASSWORD` — silent misconfiguration

| Field | Detail |
|-------|--------|
| File | `backend/internal/config/config.go` |
| Severity | **Medium** |

```go
viper.SetDefault("DB_PASSWORD", "")
```

If the variable is missing from the environment, the DSN becomes `password=` (empty). PostgreSQL may still accept the connection depending on `pg_hba.conf`, returning confusing authentication errors instead of an obvious startup failure.

**Fix**: Validate all required config fields after loading:
```go
if cfg.DB.Password == "" {
    log.Fatal("DB_PASSWORD is required")
}
```

### NM-2 · DSN built by string concatenation — special characters in password break the connection

| Field | Detail |
|-------|--------|
| File | `backend/internal/config/config.go` (`DSN()` method) |
| Severity | **Medium** |

```go
return "host=" + d.Host + " … password=" + d.Password + " sslmode=disable"
```

The libpq keyword-value format requires that values containing spaces or backslashes be quoted. A password like `"pa ss"` produces `password=pa ss` — libpq parses `ss` as the next key name and fails with a cryptic error. A password containing a single quote or backslash can corrupt the DSN further.

**Fix**: Use `pgx`'s `pgconn.ParseConfig` with a URL-form DSN where the password is percent-encoded, or use `url.QueryEscape`:
```go
u := &url.URL{
    Scheme: "postgres",
    User:   url.UserPassword(d.User, d.Password),
    Host:   d.Host + ":" + d.Port,
    Path:   "/" + d.Name,
}
return u.String()
```

### NM-3 · No `CHECK` constraints on `lat`/`lon` in terminals table

| Field | Detail |
|-------|--------|
| File | `backend/migrations/001_create_terminals.sql:7,8` |
| Severity | **Medium** |

Any DOUBLE PRECISION value is accepted for latitude and longitude. Invalid coordinates from a malformed API response (e.g. `0, 0` or `9999, 9999`) will be stored silently and rendered on the map in the ocean near Africa or off-screen entirely.

**Fix**:
```sql
lat DOUBLE PRECISION NOT NULL CHECK (lat BETWEEN 33 AND 44),
lon DOUBLE PRECISION NOT NULL CHECK (lon BETWEEN 124 AND 132),
```

### NM-4 · LIKE wildcard metacharacters in terminal name search not escaped

| Field | Detail |
|-------|--------|
| File | `backend/internal/repository/terminal_repo.go` (`SearchByName`) |
| Severity | **Medium** |

```go
WHERE name ILIKE '%' || $1 || '%'
```

`$1` is parameterized (no SQL injection), but the user's input is treated as a LIKE pattern. A search for `"station_"` matches `"stationX"` for any single character. A search for `"a%b"` matches any name starting with `a` and ending with `b`. This makes the autocomplete non-deterministic for inputs that happen to contain `%` or `_`.

**Fix**: Escape metacharacters before binding:
```go
q := strings.NewReplacer(`%`, `\%`, `_`, `\_`).Replace(query)
// Use ESCAPE '\\' in the SQL clause
```

### NM-5 · No compound index on `schedules(route_id, valid_from, valid_until)`

| Field | Detail |
|-------|--------|
| File | `backend/migrations/003_create_schedules.sql` |
| Severity | **Medium** |

The existing index covers `route_id` alone. Queries that additionally filter by date validity (which the schedule service does) still require a heap scan over all schedules for the route to apply the date filter. With hundreds of thousands of schedules this becomes a full-table scan per route lookup.

**Fix**:
```sql
CREATE INDEX idx_schedules_route_validity
    ON schedules(route_id, valid_from, valid_until);
```

### NM-6 · Admin `/status` response leaks raw ingestion error string

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/handler/admin.go` (`IngestStatus`) |
| Severity | **Medium** |

```go
"lastErr": h.lastErr,
```

If ingestion fails with an HTTP error from data.go.kr (e.g. 401 Unauthorized), the error may contain the full request URL including the `serviceKey` query parameter — effectively logging the API key in the response body of the status endpoint.

**Fix**: Store only the error message sans sensitive URL parameters, or sanitize before storing:
```go
h.lastErr = sanitizeError(err)  // strips query params from URLs in the string
```

### NL-2 · `sslmode=disable` hardcoded — no path to encrypted DB connections

| Field | Detail |
|-------|--------|
| File | `backend/internal/config/config.go` (`DSN()`) |
| Severity | **Low** |

TLS to PostgreSQL is permanently disabled. Even if PostgreSQL is configured to require TLS later, the backend will silently downgrade. Makes migration to a remote managed database (RDS, Cloud SQL) needlessly risky.

### NL-3 · Missing `Access-Control-Max-Age` header — excessive CORS preflight requests

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/middleware/cors.go` |
| Severity | **Low** |

Without `Max-Age`, browsers re-send an OPTIONS preflight before every non-simple request (Chrome: 2 hours max; Firefox: default 5 seconds). Under normal frontend traffic this can double the number of requests hitting the backend.

**Fix**:
```go
c.Header("Access-Control-Max-Age", "3600")
```

### NL-4 · Cache key built by undelimited concatenation — potential key collision

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/handler/search.go` (cache key construction) |
| Severity | **Low** |

The cache key concatenates `from`, `to`, date digits, `mode`, and `maxLegs` without separators between all components. Terminal codes are short uppercase strings today, so collision is unlikely — but the pattern is fragile if code formats ever change.

**Fix**: Use explicit separators:
```go
key := fmt.Sprintf("search:%s:%s:%04d%02d%02d%02d%02d:%s:%d",
    from, to, y, mo, d, h, mi, mode, maxLegs)
```

### NL-5 · No request-scoped timeout on search queries

| Field | Detail |
|-------|--------|
| File | `backend/internal/api/handler/search.go` |
| Severity | **Low** |

Handlers pass `c.Request.Context()` to the service but add no timeout. A slow PostgreSQL query during peak load can hold the connection and goroutine open until the client disconnects (which may never happen for automated clients). The rate limiter protects against volume, but not against per-request duration.

**Fix**:
```go
ctx, cancel := context.WithTimeout(c.Request.Context(), 5*time.Second)
defer cancel()
results, err := h.svc.Search(ctx, q)
```

### NL-6 · GitHub Actions workflow uses mutable `@master` / unversioned action refs

| Field | Detail |
|-------|--------|
| File | `.github/workflows/ci.yml` |
| Severity | **Low** |

Actions referenced without a pinned SHA (e.g. `uses: actions/checkout@v4` without a commit hash) are mutable. A compromised tag re-point can silently inject malicious code into the CI pipeline.

**Fix**: Pin to a full commit SHA:
```yaml
uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # v4.2.2
```
