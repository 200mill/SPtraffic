## Critical

### C-1 · Undefined function `kst()` in `terminal.go` — compilation blocker

| Field | Detail |
|-------|--------|
| File | `internal/api/handler/terminal.go:176` |
| Severity | **Critical** |

`currentKSTMins()` calls `kst()`, which is defined only in `search.go`. Because both files are in the same package this compiles today, but any refactor that moves `search.go` or the function will break the build silently. The coupling is invisible and fragile.

**Fix**: Extract `kst()` into a shared utility (e.g. `internal/util/time.go`) and import it from both handlers.

### C-2 · Goroutine leak in rate-limiter middleware

| Field | Detail |
|-------|--------|
| File | `internal/api/middleware/ratelimit.go:24–34` |
| Severity | **Critical** |

`time.Tick(time.Minute)` is called inside the middleware factory. `time.Tick` returns a channel backed by a ticker that is **never stopped**; the goroutine that drives it leaks for the lifetime of the process. If the router is ever re-created (e.g. in tests), each instantiation leaks another goroutine and its associated memory.

**Fix**:
```go
ticker := time.NewTicker(time.Minute)
// pass ticker to the closure; call ticker.Stop() on shutdown
```

## High

### H-1 · Ignored error from `time.LoadLocation`

| Field | Detail |
|-------|--------|
| File | `internal/api/handler/search.go:81` |
| Severity | **High** |

```go
loc, _ := time.LoadLocation("Asia/Seoul")
```

If the timezone database is unavailable (e.g. minimal Docker image without `tzdata`), `loc` is `nil` and all subsequent time arithmetic silently uses UTC, returning wrong departure times to users without any error log.

**Fix**: Check the error at startup; panic or fatal-log if `Asia/Seoul` cannot be loaded. Centralise the location as a package-level variable loaded once.

### H-2 · Timing-attack vulnerability on admin key comparison

| Field | Detail |
|-------|--------|
| File | `internal/api/middleware/adminkey.go:17` |
| Severity | **High** |

```go
if key != adminKey { ... }
```

String inequality uses short-circuit evaluation, leaking key length and prefix information through response-time differences. An attacker can enumerate the correct key character-by-character.

**Fix**:
```go
import "crypto/subtle"
if subtle.ConstantTimeCompare([]byte(key), []byte(adminKey)) != 1 { ... }
```

### H-3 · Ingestion runs with `context.Background()` — cannot be interrupted on shutdown

| Field | Detail |
|-------|--------|
| Files | `cmd/server/main.go:69`, `internal/ingestion/scheduler.go:45` |
| Severity | **High** |

Background ingestion goroutines receive `context.Background()`. A graceful shutdown signal (`SIGTERM`) closes the HTTP listener but cannot cancel an in-progress ingestion; the process hangs until the OS kills it. Mid-ingestion truncation of tables leaves the database empty.

**Fix**: Create a root `context` in `main()` cancelled by the signal handler and thread it through `Scheduler.Run` and all repository calls.

### H-4 · All schedules hardcoded to `DaysOfWeek: 127` (all days)

| Field | Detail |
|-------|--------|
| File | `internal/ingestion/scheduler.go:195, 294, 432` |
| Severity | **High** |

Every parsed schedule is marked as running all 7 days of the week (`0b1111111 = 127`). Real intercity/express-bus services often run only on weekdays or weekends. This causes the search service to return schedules on days they don't actually run, giving users incorrect results.

**Fix**: Parse the actual operation-day fields from the data.go.kr API response, or if the field is genuinely absent, document the assumption and surface it in search results.

## Medium

### M-1 · Silent schedule insertion failures during ingestion

| Field | Detail |
|-------|--------|
| File | `internal/ingestion/scheduler.go:190, 289, 427` |
| Severity | **Medium** |

```go
_ = s.schedRepo.Insert(ctx, sched)
```

Insertion errors are discarded. A transient DB error or a constraint violation silently drops schedules. The admin status endpoint will show `last_run: success` even when half the data was lost.

**Fix**: Collect errors and report a summary (e.g. `inserted X / failed Y`) in the scheduler status, and log individual failures at WARN level.

### M-2 · Silently dropped DB errors in `GetDepartures`

| Field | Detail |
|-------|--------|
| File | `internal/api/handler/terminal.go:133–139` |
| Severity | **Medium** |

`FindByRouteFrom()` and `FindByID()` errors cause a `continue` with no log. If the database is degraded, the endpoint returns a partial (or empty) result with HTTP 200, making incidents invisible.

**Fix**: Log the error at WARN and, if the failure rate exceeds a threshold, return HTTP 503.

### M-3 · Ambiguous cache-miss contract in Redis wrapper

| Field | Detail |
|-------|--------|
| File | `internal/cache/redis.go:28`, `internal/api/handler/search.go:59` |
| Severity | **Medium** |

The comment says "Returns `(nil, nil)` on cache miss" but an empty result set (`[]SearchResult{}`) is also non-nil. The handler checks `cached != nil` to detect a miss, which is correct today but fragile — any change to the return type will silently break cache-miss detection.

**Fix**: Use a sentinel error (e.g. `cache.ErrMiss`) or a boolean second return value to make the miss case explicit.

---

### M-4 · `hhmm()` parser is brittle on malformed input

| Field | Detail |
|-------|--------|
| File | `internal/ingestion/parser/util.go:17, 33` |
| Severity | **Medium** |

`hhmm()` slices the string at fixed offsets (`s[:2]`, `s[2:]`) after a length check, but does not validate that the characters are digits. A value like `"ab:cd"` passes the length check and produces `time.ParseInt` errors that are silently zeroed.

**Fix**: Use `time.Parse("1504", s)` or a regexp to validate format before slicing.

## Low

### L-1 · Ingestion phase errors logged but not returned to caller

| Field | Detail |
|-------|--------|

| Severity | **Low** |

Individual ingestion phase errors are logged with `log.Printf` (WARN) and the function returns `nil`. The admin `/status` endpoint therefore always shows success even when an entire data source failed to ingest.

### L-2 · `defer resp.Body.Close()` placed after status-code check

| Field | Detail |
|-------|--------|
| File | `internal/ingestion/client/datagokr.go:58–63` |
| Severity | **Low** |

If an early `return` happens before `defer resp.Body.Close()` is registered, the body leaks. Currently the code only returns after the defer, but the pattern is fragile under future edits.

**Fix**: Register the defer immediately after confirming `resp != nil`, before any other checks.

### L-3 · Redundant nil-guard before slice initialisation

| Field | Detail |
|-------|--------|
| File | `internal/api/handler/terminal.go:169–171` |
| Severity | **Low** |

```go
var deps []domain.DepartureInfo
// ... loop ...
if deps == nil { deps = []domain.DepartureInfo{} }
```

Go serialises a nil slice as `null` in JSON, which differs from `[]`. The nil-guard prevents that, but it can be removed by initialising directly: `deps := []domain.DepartureInfo{}`.

**Fix**: `deps := make([]domain.DepartureInfo, 0)` at declaration.

---

### L-4 · Migration directory logs noise for every non-SQL file

| Field | Detail |
|-------|--------|
| File | `internal/db/migrate.go:68–75` |
| Severity | **Low** |

The migration runner warns on every non-`.sql` file in the migrations directory (e.g. `.gitkeep`, editor swap files). In a CI log this produces false-positive warnings.

**Fix**: Only warn for files that look like they should be migrations (e.g. match `[0-9]+_*.` but lack a `.sql` extension).

### L-5 · Scheduler cron expression not validated at startup

| Field | Detail |
|-------|--------|
| File | `internal/ingestion/scheduler.go` |
| Severity | **Low** |

The cron expression `"0 2 * * *"` is a string constant. If it is ever made configurable via env var, an invalid expression will cause a silent no-op (no ingestion ever runs) rather than a startup panic.

**Fix**: Call `cron.ParseStandard(expr)` at startup and fatal-log on parse failure.
